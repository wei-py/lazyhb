# lazyhb

HBuilderX 终端工作台。项目、文件、manifest 配置和本地资源在终端操作；运行、编译、发行与云操作复用已安装版本实际提供的 CLI。

**不会自动打开 HBuilderX、开发者工具或系统文件选择器。** Web「开发运行」是明确例外：用户选择浏览器并确认后，通过真实 CLI 启动 Web 运行并打开浏览器；「仅编译」不启动浏览器。配置与资源功能无需 IDE 运行。CLI 功能需要可用的 HBuilderX 后台；未就绪时显示错误，不偷偷启动 IDE。

## 安装与运行

### mise 发行安装

GitHub Release 附件发布后，可安装对应版本：

```sh
mise use -g github:wei-py/lazyhb@0.2.1
lazyhb --version
```

发行包覆盖 macOS / Linux 的 ARM64 与 x64，包含 Bun 运行时和当前平台的原生依赖；安装机器不需要另装 Bun。Windows 暂用下方源码运行方式。

维护者在版本号与 `package.json` 一致的 `v*` tag 上运行 `.github/workflows/release.yml`，生成平台压缩包、SHA256SUMS 并上传 Release。只有 tag、没有 Release 附件时，mise 无法安装。现有 tag 若未包含该工作流，需要先把工作流提交到发布提交，再发布新版本；不要覆盖已发布 tag。

本机可用 `bun run build && bun scripts/package-release.mjs /tmp/lazyhb-release` 生成当前平台发行包。包内 `bin/lazyhb` 使用相邻 `lib/bun` 启动，保留完整依赖与 POSIX FFI 源文件，不跨平台复制原生依赖。

### 源码运行

运行时只需要 **Bun 1.4.0+**；本项目与 CI 固定使用 **Bun 1.4.2**。界面使用 OpenTUI，不需要 Node.js、Python、uv 或 `--experimental-ffi`。

```sh
bun install --frozen-lockfile
bun run start

# 直接选择项目
bun run start /path/to/project

# 指定 HBuilderX CLI
bun run start --cli /Applications/HBuilderX.app/Contents/MacOS/cli /path/to/project

# 构建后使用发布入口；入口的解释器也是 Bun
bun run build
bun bin/lazyhb.mjs /path/to/project
```

也可使用 `HX_CLI` 指定 CLI 路径。Windows 传入 `cli.exe` 的完整路径，Linux 传入已安装的官方 Linux CLI 路径；路径包含空格时加引号。PowerShell 可用 `$env:HX_CLI = 'C:\HBuilderX\cli.exe'` 设置。

启动优先级为 `--cli` > `HX_CLI` > 已保存的 CLI > 默认安装位置／PATH。显式路径必须是可执行普通文件，命令名只在 PATH 查找同名命令；无效指定不会回退到另一版本。工作台中按 `,` 打开设置，或在操作页选择「切换/配置 CLI」，可输入／浏览另一版本路径、选择已验证的历史路径或恢复自动发现。候选 CLI 完成真实 `--help` 发现且设置保存成功后才替换当前连接；失败保持原连接与选择，任务运行中禁止切换。本次 UI 明确选择优先于启动来源，「恢复自动发现」会清除本次启动覆盖并使用默认位置／PATH，不再被 `HX_CLI` 接管；后续启动仍按 `--cli` / `HX_CLI` 高于保存选择的优先级处理。

`bun run build` 后可用 `bun link` 注册本地 `lazyhb` 命令。打包使用 `bun pm pack`；原生依赖由 Bun 按目标系统安装，不要跨系统复制 `node_modules`。POSIX 安全文件操作使用 Bun 内置 C 编译器与 FFI 的小型 `openat` 包装，不调用外部编译器、Node 或 Python。Windows 使用系统文件 API，不编译这个包装。

首次运行只读发现本机 HBuilderX 当前工作区中的有效项目，导入 lazyhb 的独立列表。同名项目通过绝对路径区分。也可以在终端文件选择器中导入其他目录。

项目列表保存在系统用户状态目录，`LAZYHB_STATE_DIR` 可覆盖位置。**移除与别名只改变 lazyhb 列表，不删除源码，不冒充 HBuilderX 的“移除项目／修改项目别名”接口。** HBuilderX 的真实导入、新建、关闭命令在 CLI 任务中另行提供。

项目列表更新使用独立锁目录防止并发覆盖。异常退出留下 `projects.lock` 时，先确认没有其他 lazyhb 进程，再移除报错中给出的锁目录；程序不会擅自抢占锁。

## 操作

工作台默认进入「项目概览」，采用任务优先的页面布局：左侧固定项目列表和「项目概览 / 配置工作区 / 任务日志」导航，右侧显示当前页面，不再常驻底部日志抽屉。概览提供运行、发行、文件与项目操作入口；配置工作区保留「常规 / App / 平台」分类、字段清单及编辑能力，资源和高级工具仍可从操作入口访问。

「任务日志」是独立双栏页面：左侧为较窄的任务列表，右侧为较宽的选中任务详情与完整输出。任务记录保留所属项目、命令、运行／停止中／完成／失败／已取消状态；选择另一任务只切换显示，不中断正在运行的服务。每个任务保留最近 2,000 行输出；当前会话最多保留 100 个已结束记录，活跃任务不因历史限额被移除。重启不恢复进程或日志。工作台连接及错误通知与任务输出分开，避免把其它任务或导航提示混进选中任务的日志。

页面导航、配置页签和按钮均可鼠标点击，列表使用方向键和 Enter。底栏随当前焦点显示项目、分类、字段或日志操作提示；日志页停止入口明确标出任务编号，停止中显示等待状态。日志页可独立聚焦任务列表或输出区，切换选中任务不停止其它任务。「操作搜索」在一层菜单内保留项目／配置／资源／工具分组标记，当前页面相关操作优先；可按中英文名称或内部命令筛选。不可用项仍可查到，但会说明原因，空结果和不可用项不能执行。项目操作针对打开菜单时高亮的项目，配置／资源针对已加载项目；执行前仍保留原有确认与安全检查。

表单会按 CLI 能力使用控件：有明确枚举的参数（包括 true/false）用列表选择，`↑↓` 或鼠标选择，`Enter` 进入下一字段；可选参数提供「使用 CLI / 项目默认值」，该选项省略参数，不等同于显式传递 false。必填枚举必须选择有效值。自由文本仍用输入框，凭据仍遮罩。`Alt+↑/↓` 切换字段时保留已选值，`Ctrl+S` 应用，`Escape` 取消；应用到内存后仍须再次保存 manifest。文本框中 `Ctrl+A` 全选，`?`、数字、`[`、`]` 和空格仍是文本，不触发工作台导航。文件与图片选择器全部在终端内；建议终端至少 120×40。

云打包等引导表单的条件必填项与执行校验共用规则，例如 Android 包名、自有证书参数、iOS bundle。必填项优先显示并标注；`Ctrl+S` 检查整份表单，缺失时自动聚焦对应字段，不丢失其它字段或枚举选择，不会把包名缺失误显示成 dsyms 当前选项错误。完整回归 27 pass / 0 fail，15,901 assertions；真实 PTY 已验证从 dsyms 提交跳到缺失包名、补齐后保留 true 并成功应用，未发起云打包。

云打包非 config 模式会自动带入项目已有的非敏感配置：以当前 manifest 为优先来源，再读取项目内 `.lazyapp/platforms/android|ios/config.json` 与 `production/config.json` 的已保存标识和签名路径／别名。表单标注来源且允许修改，明确的 false / 0 不会被当作缺失。只使用当前 CLI 支持的参数和枚举；不会读取全局 IDE 缓存、猜测或解密已保存密码，不把其它项目的值带进来。已有文件损坏或不安全时明确报错，配置确实缺失时仍要求补填。证书密码继续用遮罩输入，最终确认前不执行云打包。

自动带入修复经 typecheck、build、完整 smoke（40 pass / 0 fail，15,993 assertions）及平台 smoke 验收。另在真实 PTY 使用已有项目和已安装 CLI，只读核对包名、证书文件、证书别名与来源提示；退出前取消表单，未修改项目或发起云打包。回归覆盖 manifest 优先级、项目间隔离、false / 0、缺失值、凭据不复用以及不安全配置读取。

每个已确认的 CLI 任务使用独立的本地执行实例，可同时运行多个 CLI／监听进程；各自保留输出、退出结果和取消句柄。实际目标能力仍取决于本机 CLI、插件和设备，启动多个本地实例不保证上游工具允许同时部署或编译同一项目。启动任务后进入日志页；切到概览或配置页不会停止任务。停止选中任务只取消它的本地进程树，退出工作台则先确认并等待全部任务停止。运行期间可切换到没有未保存草稿的其它项目，已有任务始终绑定启动时捕获的目标项目。活跃任务存在时禁止更换 CLI、修改配置或项目文件；文件浏览、搜索、图片预览仍可使用。候选 CLI 验证被取消后不会晚到保存或替换原连接。

本地停止不代表设备 App 已关闭或云任务已取消。远端云打包须另用当前 CLI 支持的 `pack status`／`pack cancel` 管理；详见[停止与生命周期](docs/run-publish-workflows.md#停止与生命周期)。

默认仍使用固定的 **Gruvbox Light**，不会擅自跟随终端。主题按顺序提供 **自动（终端）**、Gruvbox Dark、Gruvbox Light、Catppuccin Mocha、Catppuccin Latte、Tokyo Night、Tokyo Night Day、Solarized Dark、Solarized Light，沿用 lazymise 的语义调色板，不读写它的设置。自动（终端）读取 OpenTUI 的终端深浅检测，浅色使用 Gruvbox Light、深色使用 Gruvbox Dark，运行中收到终端模式变化时同步刷新；无法检测时保守使用深色，不覆盖已保存的自动选择。所有命名主题始终保持固定，不随终端变化。主题覆盖工作台、帮助、选择列表、表单、凭据输入和错误提示；页头、底栏及全屏空白沿用画布背景，选中页签与设置行的底色覆盖控件空白单元格。设置主题行用 `←` / `h` 选择上一项，`→` / `l` / `Enter` 选择下一项，`Esc` 关闭；只有保存成功才应用新主题，重启后保留选择。普通输入对话框中不切换主题快捷键，避免干扰输入；自动模式仍会同步终端变化。

主题、CLI 与去重历史保存在 lazyhb 状态目录的 `settings.json`，与项目列表共用 `LAZYHB_STATE_DIR` 覆盖规则（macOS `~/Library/Application Support/lazyhb`，Windows `%APPDATA%/lazyhb`，Linux `$XDG_STATE_HOME/lazyhb` 或 `~/.local/state/lazyhb`）。读取不写盘，缺失／损坏设置或未知主题回到默认；CLI 字符串只保存选择，不在读取时启动进程。写入使用权限 `0600` 的同目录临时文件再原子替换，失败保留原设置并清理临时文件。只读帮助支持 `PgUp` / `PgDn` 滚动，`Esc` 关闭恢复原焦点。

## 任务优先工作台验收（2026-10-31）

`bun run typecheck`、`bun run build`、`bun run smoke`（25 pass、0 fail、15,891 assertions）及 `bun run smoke:platform` 在 macOS arm64 / Bun 1.4.2 通过。覆盖并发任务的独立输出、退出码、单任务取消、历史保留、凭据遮罩、任务快捷切换、操作搜索的空结果／不可用保护，以及退出时父／子／孙进程清理。新增六实例验收通过引导表单实际创建两个 Web HTTP 服务、两个 Android 目标和两个 iOS 真机目标的独立 fixture 进程，核对端口、browser、deviceId、iosTarget、独立输出、鼠标选择与单任务取消；这不是六台真实设备／工具链的部署证明。POSIX 清理仅在进程组消失或全部成员经 `ps` 确认为僵尸时视为停止。

另在真实 PTY 运行源码入口，以隔离状态、临时项目和可执行 CLI fixture 启动两个真实监听进程：确认概览／配置／双栏日志切页、任务输出隔离、`Ctrl+K` 仅停止所选进程、120×40 → 64×24 → 120×40 缩放，以及退出码 0 且两个进程均已消失。临时 fixture、状态和进程已清理；未运行真实 HBuilderX 部署、签名或云打包。Windows／Linux 尚未实机验收。

操作路径优化另经真实 PTY 验证：直接输入筛选并回车打开项目属性、空结果与不可用项回车不执行、Esc 恢复原页面、底栏随字段／日志焦点变化，以及操作搜索在 120×40 → 64×24 下保持可用。仅使用临时项目与隔离状态，退出码 0，临时目录已清理。

## 已实现

### 配置

- 22 个分类入口：基础、Android/iOS 图标／启动界面／模块／权限／原生插件／常用其它、鸿蒙 App、Web、九类小程序、快应用、鸿蒙元服务、uni统计2.0、源码。
- 已核实字段的类型化表单；对象和数组使用字段级 JSON 编辑器。已有扩展字段可查看、修改、增加、删除，**不以一个整文件源码框代替配置分类**。
- 扩展字段采用 JSON Pointer，例如 `/app-plus/distribute/android/minSdkVersion`。字符串值写成 `"text"`，布尔值写 `true`，对象／数组按 JSON 输入；路径中的 `/` 与 `~` 分别转义为 `~1`、`~0`。
- 根目录与 `src/manifest.json` 自动识别；普通 uni-app 与 uni-app x 使用不同配置节点。不会把 classic 的 `app-plus/h5` 直接套到 x 的 `app-android/app-ios/web`。
- 字段编辑保留周围 JSON5/JSONC 注释和未建模字段；直接替换某个对象的值时，该对象内部文本由新值替代。保存前解析校验；无效源码保留在编辑器中，不丢弃草稿；检测外部修改并拒绝覆盖；同目录原子保存。已有 manifest 损坏时仍可从文件管理修复，返回后自动加载。
- 启用 classic 模块写入模块对象；关闭模块时可保留全部 Android 权限，或显式选择要一并移除的权限。**不自动猜测权限属于哪个模块，也不擅自删除共享／用户权限。**
- x 的 Vapor 开关保留样式隔离与渲染目标联动。旧版本和不支持的平台仍受官方工具链限制；已有未知字段不会被清除。
- 源码编辑应用到内存后仍需保存；切换项目、打开文件管理、执行 CLI 或退出前处理未保存修改。

源码和对象／数组的 JSON 编辑器展示原始内容，可能包含文件中已有的密钥；不要在共享终端或录屏中打开这些原始视图。遮罩用于专门的凭据字段输入，不会把原始文件伪装成已经脱敏。

保存采用乐观冲突检查：写入前核对磁盘指纹，并以原子替换发布；不是文件系统 CAS，也不能阻止不配合的外部编辑器在最后一次检查与替换之间竞争。请勿让多个程序同时写同一 manifest。

### 图标和启动资源

- 由原图生成 classic Android、iPhone、iPad、App Store 的全部声明槽位，或 x Android 与 App Store 槽位；真实写入 PNG 并回填配置。
- 输出 `unpackage/res/icons/android-尺寸.png`、`ios-尺寸.png`；iOS 透明背景合成到选定背景色，输出无 alpha 的 RGB PNG。非正方形原图采用居中裁切。
- 可保留所有已配置手动图标，包括对应文件；生成目标冲突时不会覆盖受保护引用。关闭保留策略才替换既有生成文件。原图不被覆盖。
- 手动选择单个图标也检查 PNG 内容、槽位尺寸及 iOS alpha，而不仅检查扩展名。
- 校验 PNG、Android `.9.png` 边框／拉伸标记、storyboard ZIP 的目录、大小、XML 与图片引用。此校验不冒充原生编译器验证。
- 从图片生成带 aspect-fit 约束的 iOS storyboard ZIP，写入唯一文件并关联配置；配置关联失败时撤销该次配置修改并删除 ZIP。
- 图片、ZIP 和导入插件属于立即发生的磁盘操作；manifest 仍显式保存。放弃 manifest 修改不会删除已经成功生成的资源，可在文件管理中查看。

### 本地原生插件

校验 `_dp_nativeplugin` 元数据、平台目录、导出模块及集成类型，再复制到 `nativeplugins/<id>`，以原子无覆盖移动发布完整目录，更新 `app-plus.nativePlugins`。不覆盖已有不同目录，不接受链接／特殊文件。已有本地插件也可重新校验并关联。

这不是云插件购买／授权，也不是 uni_modules 导入。x 项目拒绝 classic 原生插件导入；可用的 UTS/uni_modules 命令在 CLI 中提供。

### 项目文件

终端文件树、UTF-8 编辑／保存、新文件／目录、重命名、复制、移动和文字搜索。修改现有文件时检测外部变化；目标已存在则不覆盖。文件操作限制在项目内，拒绝路径穿越、符号链接和 Windows reparse point；没有删除项目源码的操作。

单文本文件最多 2 MiB；搜索最多 200 条，跳过 `.git`、`node_modules`、`unpackage`、`.venv` 和二进制文件。重命名／移动不自动修复代码引用；跨文件系统移动报错，不退化为复制后删除。

文件／目录图标使用 [UnoCSS Icons preset](https://unocss.dev/presets/icons) 同源的真实 Iconify SVG 数据：`@iconify-json/vscode-icons` 1.2.94（VSCode Icons 13.0.0，Roberto Huertas，[MIT](https://github.com/vscode-icons/vscode-icons/blob/master/LICENSE)）。终端不运行 UnoCSS 的 CSS 类，也不使用 emoji／Nerd Font 冒充图标。`file-icons.ts` 按真实目录属性优先分类，再按文件名、扩展名匹配；未知类型使用集合的默认文件／文件夹图标。同名文件与目录不会混淆。Iconify utils 处理尺寸与别名，首次用到时才将 SVG 转为 PNG，并按图标 ID 缓存进行中的转换与结果；运行时完全离线，不请求 CDN。

图片预览在终端内显示实际图形，不打开外部窗口。支持 PNG、JPEG、WebP、GIF（首帧）、SVG；输入最多 16 MiB、解码最多 16,777,216 像素，最长边缩至 2048 像素，解码超时 5 秒。读取遵循同一项目边界与链接拒绝策略；损坏、超限或不安全 SVG 显示错误而不进入文本编辑。SVG 拒绝实体／DOCTYPE、脚本、外部资源和嵌入内容。透明区域承接主题背景，图像按终端单元格比例适配；`Esc` 关闭预览回到原目录并保留选择。文件列表使用 `j` / `k` 或 `↑` / `↓` 选择，`Enter` / `l` 进入选中目录或打开选中文件（特殊菜单行保持 Enter 语义），`o` 打开操作菜单，`←` / `h` / `Backspace` 返回上级并保留原选择，不越过项目根目录，`Esc` 返回配置。`h` / `l` 的目录操作仅限项目文件列表；工作区仍切换面板，文本编辑中仍输入字符。

文件列表与独立图片预览采用不同降级策略：列表只有在实际支持 Kitty／Sixel 原生图形协议时才显示离线 Iconify 图标；普通 `blocks` 终端或没有原生图形能力时，使用紧凑、对齐的单行类型列，例如 `JS`、`JSON`、`MD`、`YAML`、`PNG`，并区分目录与普通文件，不再绘制低分辨率块图标，也不为文字降级转换图标 PNG。文字是明确的类型提示，不冒充图标。独立图片预览仍使用 OpenTUI `ImageRenderable` 的 `auto` 协议，在普通终端以大画布彩色 `blocks` 显示实际图片，不全局禁用图像。原生协议受控 renderer 测试不等于实际终端支持或实机截图。

POSIX 文件管理通过目录描述符与 `O_NOFOLLOW` 固定访问位置；Windows 检查 reparse point，但不承诺抵御恶意进程在校验后并发替换父目录。

### CLI 任务

- 从实际 `cli --help` 发现命令、参数、枚举及版本默认值，合并重复命令变体；没有写死一个假支持列表。可执行本机暴露的项目、设备、编译、发行、打包状态／取消、日志、云开发、托管、模块和语言服务等命令。
- 项目上下文菜单的运行／发行作用于菜单目标，不暗中沿用另一个已加载项目。未保存草稿先处理；取消保持原项目与草稿。任务确认展示目标绝对路径与最终执行模式。
- 运行与发行入口从当前 CLI 能力动态分类；没有适用能力时明确提示，不编造菜单支持。`launch` 必须显式提交当前版本枚举允许的 `ui=false` 或 `ui=0`。Web 支持 `compile=false` 时开放实际运行，支持 `compile=true` 时保留仅编译；普通 `mp-*`／`quickapp-*` 仍只开放仅编译。App 仅允许编译时也显示仅编译；iOS 不开放模拟器。
- 项目任务只使用明确的 `project`／`projectPath`／`prj` 选择器锁定目标，不把可能表示产物目录的 `path` 当项目。缺少已识别选择器时明确拒绝项目上下文执行，不能回退到 IDE 当前项目。`pack status`／`pack cancel` 绑定当前目标，属于打包管理而不是创建云包；云开发与独立托管命令仍在高级 CLI 中。
- 普通参数留空表示省略；无值开关填 `@flag`。项目上下文任务的目标参数锁定，不在表单中编辑；仅编译入口必须提交 `compile=true`，清空或修改为其它值会拒绝继续，不能省略后依赖 CLI 隐式默认。
- 参数表单之后再次确认，默认选择取消；取消／确认选项保持可见。长项目路径与风险摘要可用 `Tab` 聚焦后以 `↑`／`↓`、`j`／`k`、`Home`／`End` 滚动，也可用 `PgUp`／`PgDn` 翻页。输出实时流入有上限的日志，不经 shell 拼接命令。
- Android、iOS 真机与鸿蒙元服务可用设备运行模式；最终确认根据提交的 `compile` 参数区分运行与仅编译。Web 实际运行显式提交 `compile=false`，选择当前 CLI 支持的浏览器并在确认页提示浏览器启动；仅编译仍显式提交 `compile=true`。常规小程序／快应用保留仅编译限制。禁止 IDE 接管、IDE 打开／退出／更新、iOS 图形模拟器启动及未暴露纯 CLI 模式的旧版运行命令。
- 本地 CLI 取消不等于远端云打包取消；使用真实 `pack status`／`pack cancel` 查询、取消云任务。
- 云打包参数转成仅当前用户可读的临时 JSON 配置，完成／取消后清理，避免口令进入进程 argv。已有 `--config` 文件经安全读取、目标项目校验后形成私有执行快照；配置与其他参数不能混用，用户文件不会被删除。
- 提交的凭据从日志中隐藏。仅支持 argv 口令传递的账号登录等操作不开放，使用已有登录态；不保存账号口令到工作台状态。

### 运行与发行工作流

先选择目标项目，再用 `r` 或 `Shift+R` 选择目标与模式，填写该模式所需参数，最后核对目标绝对路径、产物和风险。**开发运行的仅编译不等于生产发行编译**，生成资源也不等于已经获得安装包或完成上架：

- App／鸿蒙元服务区分设备运行与仅编译。设备列表按目标平台查询并显示 CLI 原始输出；没有约定的输出格式时，不猜设备 ID。Android 与 iOS 真机可分别创建多个任务；建议为每个任务指定 deviceId，任务列表与详情保留该设备标识，iOS 显式绑定 `iosTarget=device`。标准／自定义基座仍受对应平台和现有基座限制。
- Web 可同时创建多个项目的实际运行任务，浏览器和配置端口显示在任务详情。启动前分别设置 classic 项目的 `h5.devServer.port` 或 uni-app x 的 `web.devServer.port`；没有专用 `--port` CLI 参数时不会伪造参数、自动修改 manifest 或将配置值冒充实际监听地址，最终地址以 CLI 日志为准。同一项目、同一设备或相同端口可能争用上游构建／部署资源，工作台的独立任务不保证工具链允许任意重复运行。
- 普通小程序／快应用的开发入口仅编译，不启动开发者工具。IDE 接管与图形模拟器仍受原约束限制；Web 浏览器启动仅在用户主动确认的实际运行模式允许。
- Android／iOS／鸿蒙的 `appResource` 与 `wgt` 分别选择。前者是本地打包资源，后者是更新资源包，不是 APK／IPA。鸿蒙本地打包与资源生成也分开：官方发布流程产出签名 `.app`，`.hap` 属于运行包等场景，不能混称。
- Web 生产构建与 uniCloud 托管上传分开；微信／支付宝的生产资源、混合分包与 CI 上传分开。上传需要真实账号、空间／AppID、密钥和相应插件；本机帮助声明上传与混合分包互斥。上传不是审核或上架。
- App 云打包按 Android／iOS 平台和证书模式准备条件字段，配置文件方式与参数方式不混用。配置中的项目必须与确认目标一致；不在确认后重新读取一个可能已被替换的配置作为执行目标。
- 云打包状态／取消绑定目标项目；取消平台使用当前 CLI 的 `app-android`／`app-ios`，不同于创建云包的 `android`／`ios`。当前官方和本机帮助没有远端任务 ID 参数，本地任务编号不能代替它。

入口与字段始终取决于当前 CLI 的实际能力；切换版本后重新发现，不把在线最新文档当作本机支持证明。完整参数条件、版本差异、官方原文与本轮只读调查见[运行发行矩阵](docs/run-publish-workflows.md)。实际设备部署／签名／云发行仍属于下列未验证边界。
